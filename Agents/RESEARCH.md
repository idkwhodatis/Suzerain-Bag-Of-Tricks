# RESEARCH — decompile + variable catalog workflow

All output → `GameDump/<gamever>/` (gitignored). Commit only distilled
findings into `Agents/API.md` (add rows / confirm status there; tables are
generated by `Utils/gen_api.py` — extend the generator, don't hand-edit).
Never commit full decompiled game code.

## 1. Version stamp

- Game build: Steam build id + in-save `version` field (e.g. `3.1.0.1.153`).
- SMK release + MelonLoader version. One `GameDump/<gamever>/` per game build.

## 2. Assembly dump (MelonLoader path — Cpp2IL/Il2CppDumper cannot parse metadata v39)

- Cpp2IL (max v29.x) and Il2CppDumper (max Unity 2022.2) both predate this build. Use instead:
- With MelonLoader installed + one game launch, `MelonLoader/Il2CppAssemblies/` holds `Assembly-CSharp.dll` + `Assembly-CSharp-firstpass.dll` (type/member metadata, no method bodies).
- Enumerate metadata-only with `Utils/metadump` (net8.0 +
  System.Reflection.Metadata; game stays running-safe). Build:
  `dotnet build Utils/metadump -c Release`. Run:
  `dotnet Utils/metadump/bin/Release/net8.0/metadump.dll <dll> ns|types|members|strings [filter]`
  (`ns` = namespaces by count; `types <ns>` = types + member counts, empty
  filter = global namespace; `members <Type>` = methods/fields/properties/events;
  `strings [substring]` = deduped `#US` literals).

## 4. Live confirmation (F9 dump + SMK overlay)

- Fast path: load a campaign, press F9 (BagOfTricks `Dump`) → timestamped
  `UserData/BagOfTricks/dump_*.txt` with all 2440 catalog keys (live
  presence + runtime values). Diff against save-mined expectations to
  confirm rows in `Agents/API.md`.
- Manual path: Ctrl+D overlay in menu (expect "GameFlowManager not loaded!")
  then in a loaded campaign browse live vars; or F10 menu to flip a known
  key (e.g. `BaseGame.GovernmentBudget`) and observe the HUD; revert.
- Log keys present in-game but missing from FIELD_MAP → unknown-key list →
  resolve via dump context + turn/trigger notes → regenerate catalog.

## 5. Catalog format (`Agents/API.md`)

`| Field | Key | Notes |` per UI group, plus an Ungrouped section and a
Changelog table. Seed rows come from FIELD_MAP; append newly discovered
keys with dump reference (class/method, not pasted code), then regenerate
via `Utils/gen_api.py`. Mark unconfirmed rows via the file's status header
until confirmed live; stamp the pinned game version in the Changelog.

## 6. Save-editor cross-reference

- Format spec: `Utils/Parser.py` (`Variable={["K"]=V, ...}` + type coercion).
- Semantics: `Utils/Consts.py` GROUP_* tells you which screen/system a key
  belongs to (Money/Economy/Opinion/Assembly/...). Mirror preset semantics
  (e.g. `maxMoney`) when implementing live presets.
- Save-editor is ~1yr stale: treat its maps as hypotheses until re-confirmed
  against the pinned game version.

## 7. Mining pipeline (`Utils/`, run in order from repo root)

All scripts run with the save-editor venv python. Absolute machine paths
live in `REPO`/`CONSTS` constants — edit when moving machines.

1. `Utils/mine_saves.py` — parses every save's `variables` string
   (`%LOCALAPPDATA%Low\Torpor Games\Suzerain\*.json`) → key universe.
   Writes `GameDump/3.1.0.1.175/mining/universe.json` + `saves.json`.
2. `Utils/analyze_saves.py` — FIELD_MAP coverage, turn variance over two
   full campaigns, GameCondition/SharedSupport/HUDStat listings.
   Writes `.../mining/analysis.json`.
3. `Utils/build_extras.py` — curates mined keys → `Utils/api_extras.json`.
4. `Utils/gen_api.py` — renders `Agents/API.md` (self-checks every key).
5. `Utils/gen_keys.py` — flattens all catalog keys → `src/Keys.cs`
   (in-game F9 dump list; rebuild the mod after).
6. `Utils/drift.py` — version drift + globally-static census →
   `.../mining/drift.json`.
7. DialogueDB content (`db_dump.py` → `db_table.py` → `conv_mine.py`): UnityPy scratch venv
   loads `StreamingAssets/aa/.../database_assets_all_*.bundle`, dumps
   `Suzerain.asset` typetree → `GameDump/<gamever>/db_tree.json` (~300MB);
   `db_table.py` extracts the variable table (name/type/initial/description)
   → `.../mining/db_variables.json`, merged by `gen_api.py` into catalog notes;
   `conv_mine.py` extracts every `Variable[".."]` mention in entry
   conditions/scripts → `.../mining/conversation_refs.json` (trigger/effect
   map: who sets/gates each key). Bundle hash in filename changes per build.
8. `Utils/save_thresholds.py` — per mapped key: condition/write counts,
   conversation spread, numeric comparison ladders → `.../mining/thresholds.json`.
9. `Utils/build_triggers.py` — condenses `conversation_refs.json` to per-key
   write/gate summaries → `.../mining/triggers.json`, merged by `gen_api.py`
   into catalog notes (`Trig: NW/NC, set:…, gates:…`).
10. `Utils/live_compare.py` — F9 dump values vs DB initials (bool-cast
    artifacts filtered) → `.../mining/menu_deviations.json`. Menu-state
    values matched the last campaign end-state (residual table, cross-
    validates saves vs live memory); Retrograde sentinel reads
    -1000000000 live vs -999999999 in DB.
11. `Utils/validate_api.py` — structural gate over `Agents/API.md`
    (column counts per table, stray-marker scan). Run after every regen.
